## Результаты

| Модель | CV RMSE log | RMSE log | MAE log | R² log | RMSE, $ | MAE, $ | R² USD |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Linear Regression | 0.1215 | 0.1172 | 0.0810 | 0.9264 | 20,744 | 13,649 | 0.9439 |
| Ridge | 0.1138 | 0.1195 | 0.0831 | 0.9235 | 21,957 | 14,375 | 0.9371 |
| Lasso | 0.1078 | 0.1183 | 0.0798 | 0.9250 | 21,033 | 13,663 | 0.9423 |
| ElasticNet | 0.1082 | 0.1183 | 0.0798 | 0.9250 | 20,984 | 13,641 | 0.9426 |
| Stacking (бонус) | — | 0.1181 | 0.0786 | 0.9253 | 21,189 | 13,588 | 0.9415 |


Основная модель — **Lasso**, выбранная по минимальному CV RMSE log на
обучающей части. Разделение фиксировано: 1168 домов для обучения и 292 для проверки.
Из train по предметному правилу исключены Id 524 и 1299; финальное обучение — 1166 домов.
Проверочная часть не фильтруется. На данном holdout Linear Regression немного лучше
по RMSE; выбор Lasso сохраняется по CV, без повторного выбора после оценки holdout.
Stacking не улучшил RMSE основной модели в этом запуске.

RMSE и MAE вычислены отдельно для log1p цены и для долларов. R² log и R² USD
относятся к разным целевым переменным. Время финального обучения, поиска параметров
и оценки каждого фолда приведены в `models/metrics.json`; время зависит от компьютера.

## Предобработка

Каждая модель — полный Pipeline: смысловые пропуски, медиана LotFrontage по району,
числовые медианы train, новые признаки, порядковое кодирование, One-Hot и StandardScaler.
Статистики обучаются заново внутри каждого CV-фолда. Неизвестные категории обрабатывает
кодировщик; новые признаки создаёт [house_price_pipeline.py](house_price_pipeline.py).
`Id` и целевая переменная не входят в признаки. Формулы новых признаков и ограничения
интерпретации коэффициентов объяснены в ноутбуке.

## Воспроизведение

Нужен Python 3.12. Запускайте ноутбук из папки `module-2-house-prices`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Откройте ноутбук в Jupyter или VS Code, выберите это окружение и выполните ячейки
по порядку. Ввода через `input()` нет. Все пути к данным заданы относительно модуля.
В разделе 11 по умолчанию загружается модель с GitHub raw и сравниваются три прогноза.
Ветка по умолчанию — `main`; другую ветку или коммит можно задать переменной
`HOUSE_PRICES_GITHUB_REF`. Для запуска без сети задайте `HOUSE_PRICES_CHECK_GITHUB=0`
в окружении ядра. В этом случае результат отмечается как локальная проверка.

## Использование сохранённой модели

Рядом должен находиться `house_price_pipeline.py`; зависимости берутся из `requirements.txt`.
Модель уже содержит всю подготовку данных. Передаются исходные столбцы, без ручного One-Hot.

```python
import joblib
from house_price_pipeline import predict_price

model = joblib.load('models/best_model.pkl')
house = {'OverallQual': 6, 'GrLivArea': 1500, 'YearBuilt': 2000, 'YrSold': 2010}
price = predict_price(house, model)
print(round(price, 2))
```

Минимальный пример заполняет остальные неизвестные поля по обученным правилам.
Для содержательного прогноза лучше передавать все известные характеристики.
Полные данные пяти домов находятся в `examples/demo_houses.json`, а сравнительная
таблица их цен — в `examples/demo_predictions.csv`.
Файлы joblib берите только из доверенного источника: загрузка может выполнять Python-код.

## Файлы

- `data/` — исходные CSV, описание категорий и сводка датасета.
- `models/lr_model.pkl`, `ridge_model.pkl`, `lasso_model.pkl`, `enet_model.pkl` — четыре полных Pipeline.
- `models/best_model.pkl` — выбранная по CV основная модель; `stacking_model.pkl` — бонус.
- `models/scaler.pkl`, `feature_cols.json`, `preprocessing_state.json` — дополнительные сведения о подготовке.
- `models/metrics.json`, `metadata.json` — фактические результаты и параметры запуска.
- `models/repository_verification.json` — источник загруженной модели и результат проверки.
- `models/verification.json` — результат независимой проверки артефактов.
- `examples/` — EDA, прогнозы, остатки, коэффициенты и таблицы проверочных прогнозов.
- `submission.csv` — 1459 положительных прогнозов для Kaggle test; меток для локальной оценки нет.
- `verify_artifacts.py` — проверка метрик, моделей, новых входов и структуры отчёта без переобучения.

Проверка GitHub raw выполнена: три прогноза совпали.
